Сейчас выполняем ТОЛЬКО первый этап — персонализация игроков.

Не трогай пока фотографии сценариев, стартовые/финальные изображения, подсказки и механику сценариев. Это будет отдельным следующим этапом.

## Цель

Вместо текущего экрана:

«Выберите количество игроков → введите имена»

сделать постоянный набор из 6 слотов игроков с именами и аватарами.

Перед созданием новой партии приложение автоматически определяет, сколько игроков участвует, по наличию аватаров.

---

## 1. Конфигурация игроков

Создай:

`author/players.json`

В нём должны храниться имена шести возможных игроков по стабильным ID:

1
2
3
4
5
6

Пример структуры:

```json
{
  "1": { "name": "Игрок 1" },
  "2": { "name": "Игрок 2" },
  "3": { "name": "Игрок 3" },
  "4": { "name": "Игрок 4" },
  "5": { "name": "Игрок 5" },
  "6": { "name": "Игрок 6" }
}
```

Я должен иметь возможность в будущем просто открыть этот файл и заменить имена, не меняя код.

---

## 2. Аватары

Создай папку:

`author/players/`

и подготовь:

`1.jpg`
`2.jpg`
`3.jpg`
`4.jpg`
`5.jpg`
`6.jpg`

Сейчас создай в этих файлах простые ЗАГЛУШКИ, чтобы я сразу видел, где находится фотография каждого игрока.

Заглушки должны быть визуально различимыми и содержать номер игрока, например:

«PLAYER 1»

«PLAYER 2»

и т.д.

Важно: это именно временные изображения-заглушки.

В дальнейшем я просто заменю:

`1.jpg` → фотография игрока 1
`2.jpg` → фотография игрока 2
и т.д.

Код при этом менять не потребуется.

---

## 3. Автоматическое количество активных игроков

Не спрашивай количество игроков вручную.

Количество игроков определяется по наличию фотографий.

Минимум — 4 игрока.
Максимум — 6 игроков.

Используй последовательные слоты.

Нормальные варианты:

### 4 игрока

есть:

`1.jpg`
`2.jpg`
`3.jpg`
`4.jpg`

нет:

`5.jpg`
`6.jpg`

→ активны игроки 1–4.

### 5 игроков

есть:

`1.jpg`
`2.jpg`
`3.jpg`
`4.jpg`
`5.jpg`

нет:

`6.jpg`

→ активны игроки 1–5.

### 6 игроков

есть:

`1.jpg`
`2.jpg`
`3.jpg`
`4.jpg`
`5.jpg`
`6.jpg`

→ активны игроки 1–6.

Если обнаружена неправильная конфигурация, например:

`1.jpg`
`2.jpg`
`3.jpg`
`5.jpg`

но нет `4.jpg`,

НЕ пытайся автоматически переставлять игроков.

Покажи понятную ошибку конфигурации:

«Проверьте фотографии игроков. Игроки должны идти последовательно от 1.»

То же самое для любых других пропусков.

Количество игроков должно определяться ДО создания новой партии.

---

## 4. Начальный экран

Сейчас начальный экран позволяет выбрать количество игроков и ввести имена.

Полностью убрать эту логику.

Теперь начальный экран должен показывать уже подготовленных активных игроков:

* аватар;
* имя.

Например:

[фото] Иван
[фото] Алексей
[фото] Мария
[фото] Олег
[фото] Анна

Если активных игроков 4 — показываются 4.

Если 5 — 5.

Если 6 — 6.

Никакого выбора количества игроков вручную.

Никакого ввода имён перед каждой партией.

Имена берутся из `author/players.json`.

---

## 5. Создание состояния партии

При создании новой партии передавай в `createGame()` уже подготовленный массив активных игроков.

Каждый игрок должен иметь стабильный ID:

1, 2, 3, 4, 5 или 6.

Не генерируй новый случайный ID.

Игрок должен выглядеть концептуально так:

```text
id
name
avatar
остальные существующие игровые параметры
```

Существующие игровые параметры игрока не удалять и не менять без необходимости.

---

## 6. game-engine.js

Измени только необходимое для того, чтобы движок принимал игроков со стабильными ID.

НЕ меняй алгоритмы:

* выбора жертвы;
* выбора виновника;
* выбора сценария;
* ходов;
* мини-игр;
* подсказок;
* обвинений;
* завершения партии.

`selectVictim()` и `selectCulprit()` должны продолжить работать с массивом игроков как раньше.

Главная задача этого этапа — заменить случайные ID игроков на стабильные ID из конфигурации.

Не делай масштабный рефакторинг `game-engine.js`.

---

## 7. Аватар + имя

Создай одну общую функцию/компонент отображения игрока:

**аватар + имя**

Используй его во всех существующих интерфейсных местах, где игрок показывается как отдельный объект.

Например:

* список соперников;
* текущий игрок;
* выбор соперника;
* выбор победителя;
* награда;
* список обвиняемых;
* подтверждение обвинения;
* сообщение о выбывании;
* победитель;
* жертва при отдельном отображении;
* виновник при отдельном отображении;
* другие места, где сейчас отдельно выводится имя игрока.

Не создавать для каждого экрана отдельную реализацию.

---

## 8. Подсказки и текст сценариев

На этом этапе НЕ менять отображение подсказок.

В подсказках:

**только имя игрока.**

Никаких аватаров внутри текста.

То же самое касается обычного текста сценария.

Если сейчас движок подставляет имя игрока в текст через `[ВИНОВНИК]`, `[ЖЕРТВА]`, `[СВИДЕТЕЛЬ]` и другие существующие метки — оставить это как есть.

Не менять структуру подсказок ради аватаров.

---

## 9. Сохранение

Не ломай существующий `storage.js`.

Новая партия должна сохранять игроков с их стабильными ID, именами и avatar path.

Старые сохранённые партии, в которых были случайные ID и нет avatar path, должны продолжать открываться.

Для старых партий отсутствие аватара не должно приводить к ошибке.

## 13. Проверка после реализации

После изменений обязательно проверь:

1. Запуск с 4 игроками.
2. Запуск с 5 игроками.
3. Запуск с 6 игроками.
4. Правильное отображение аватара + имени.
5. Что имена берутся из `author/players.json`.
6. Что при новой партии используются актуальные имена.
7. Что стабильные ID игроков равны 1–6.
8. Что выбор жертвы работает.
9. Что выбор виновника работает.
10. Что старые механики партии не изменились.
11. Что подсказки по-прежнему показывают только имена без аватаров.
12. Что неправильный пропуск слота фотографий вызывает понятную ошибку.
13. Что отсутствие `5.jpg` и `6.jpg` корректно означает 4 игроков.
14. Что отсутствие только `6.jpg` корректно означает 5 игроков.
15. Что наличие всех шести фотографий означает 6 игроков.

После завершения НЕ вноси никаких дополнительных улучшений.

В отчёте укажи:

* какие файлы изменены;
* какие новые файлы созданы;
* как определяется количество игроков;
* где находятся фотографии-заглушки;
* как мне в будущем заменить имена и фотографии;
* какие части существующей игровой логики были оставлены без изменений.
